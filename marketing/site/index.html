02 / SMALL BY DESIGN

Evidence first.
Conclusions later.

A useful starting point for your next CI investigation.
Keep the data close and the claims honest.

[01]

Follow the attempts.

Keep job executions tied to their provider attempt. Inherited jobs and missing identities don't become invented reruns.

[02]

Know what's missing.

Run caps, request limits, and missing data stay visible. Partial coverage has its own exit code and explicit reasons.

[03]

Own the snapshot.

Reduced metadata, written locally. No source code or raw logs collected. No hosted dashboard required.

03 / TRY IT FROM SOURCE

Bring a repo.
Leave with evidence.

Node.js 24.x · npm · a GitHub repository
Public repositories work with anonymous access.

Read all options ↗
QUICK START / LOCAL CHECKOUT
git clone https://github.com/HaMZAAsif043/CI-Efficiency-Auditor.git
cd CI-Efficiency-Auditor
npm ci
npm run build
node dist/cli/main.js collect --repo cli/cli --days 7 --max-runs 1 --max-requests 8 --out snapshot.json --no-cache --anonymous

With a one-run cap, exit 3 usually means a valid partial snapshot. Private repositories need your own token with Actions read access. Keep private metadata local.
